# Internationalization (i18n)

ShiritaiBot ships in Simplified Chinese (`zh-CN`, the reference language) and English (`en`). This page explains how text is translated and the rules for adding new text.

**Chinese is the default everywhere.** Another language is used only when someone chooses it: `/lang`, the global default in Settings, or the WebUI language switch. Nothing is guessed from the language a user writes in, the browser's language or `Accept-Language`.

## Four separate settings

| Layer | What it covers | Where it's set |
|---|---|---|
| **Interface language** | WebUI text (fully translated) | Per browser: top-bar switch or **Settings → General → Language**. Saved in `localStorage`; otherwise the bot language. Chinese before sign-in, when the bot language isn't known yet. |
| **Bot language** | Fixed text the bot sends: `/help`, errors, notifications | `Settings.locale` is the global default. `/lang` overrides it for one session (stored as the `session_locale` record). |
| **Model language** | Which version of the prompts the model gets | Same as the bot language of the session. |
| **Region** | Time zone, date and number formats | One owner time zone, `proactive.timezone`, used by the dashboard, calendar and statistics. Formats follow the interface language. |

### How a session's language is picked

1. The session's `/lang` override, if any. It is **forced**: replies use it even when the user writes in another language, and even when the persona asks for another one.
2. Otherwise `Settings.locale`, Simplified Chinese out of the box. Replies use it even when the user writes in another language. A persona that names a reply language (for example "answer in Japanese") still wins here.
3. Background (proactive) work uses the language of the owner chat it reports to (`Settings.owner_notification_session()`).

API requests use the WebUI's `X-ShiritaiBot-Locale` header, else `Settings.locale`.

`/lang` is stored apart from `SessionPolicy` on purpose. A policy entry replaces the session's defaults wholesale, so storing the language there would freeze the session's mode and tool permissions.

`/lang` usage: `/lang` shows the current language, `/lang en` or `/lang zh-CN` sets it (aliases such as `zh`, `中文` and `english` work too), and `/lang default` removes the override. Only the owner can change it.

## Where text goes

| Kind of text | Put it in | Look it up with |
|---|---|---|
| Backend text people read (errors, command replies, notifications) | `src/shiritaibot/locales/<locale>/<namespace>.json` | `t("namespace.key", name=value)` or `PublicError("namespace.key", name=value)` |
| Text sent to the model (personas, instructions, captions) | `src/shiritaibot/prompts/zh.py` and `en.py`, same constant names | `prompt("NAME", locale)` |
| WebUI text | `web/src/locales/<locale>/<namespace>.json` (one namespace per page or area) | `i18n.t("ns:key")` or `useTranslation()`; `tx()` for keys stored in data |
| Language rules (emotion phrases, relative-time words, stopwords) | Keep them in code as lists for **all** languages at once. Chinese matches as a substring; English must match whole words. | — |

### Keys and placeholders

- Keys describe meaning, not wording: `commands.lang.owner_only`, not `commands.only_the_owner_can`.
- The backend key is the file name followed by the path inside the file: `lang.owner_only` in `commands.json` is `commands.lang.owner_only`. The WebUI uses `namespace:path`, for example `settings:language.botLabel`.
- Placeholders use single braces on both sides: `"Language: {name}"`. In backend catalogs, write literal braces as `{{` and `}}`. In WebUI catalogs, literal JSON such as `{"stream":false}` is left alone; only `{word}` is a placeholder.
- Plurals: add `key_one` and `key_other` and pass `count`. Chinese only needs `key_other`; the check treats the forms as one key.
- Every locale must have the same keys and the same placeholders as `zh-CN`. CI checks this.

### Rendering happens when text is shown

`PublicError` and `Text` keep the key and parameters and render them when converted to a string. The same error is English in an English WebUI request and Chinese in a Chinese chat.

Text that isn't a catalog key is returned unchanged. That means existing Chinese literals keep working while code is migrated one module at a time. In the WebUI, `tx()` does the same for field specs.

### WebUI patterns

- **New namespace**: add `web/src/locales/zh-CN/<ns>.json` and `en/<ns>.json`, then add the zh-CN file to `web/src/locales/reference.ts` so keys are type-checked. Catalogs load automatically.
- **Never translate at module load.** A constant outside a component is evaluated once, so it would stay in the first language. Store the key and translate where it renders with `tx()` (for example `label: "models:routes.chat.label"`), or use a getter: `get label() { return i18n.t("permissions:risk.safe.label"); }`. Field specs in `config/schema.ts` hold keys, and `FieldForm` and `PageTabs` translate them.
- **Don't base logic on display text.** Use stable IDs (`id === "cost"`) and translate only what's shown.
- **Sentences with markup** (`<code>`, `<strong>`) use `<Trans>` with named tags, so each language can place them: `"Run <code>{helper}</code>"`.
- **Dates, weekdays and month names** come from `Intl.DateTimeFormat(currentLocale(), …)`, not catalogs. Numbers use `formatNumber()`.
- **Joining lists**: use `common:enumSeparator` (、 / ", ") or `common:listSeparator` (； / "; ").

### Prompts

- The Chinese constants in `prompts/zh.py` must stay byte-identical to what earlier versions sent, so existing behavior and prompt caches don't change. `tests/test_i18n.py` checks this.
- Internal model calls that return structured data, such as memory extraction and triage, are not forced into the session language. Memory evidence must be quoted from the original text exactly as written.

## Backend patterns

- **Language follows the context.** `t()` uses the request's or turn's language; outside one (scheduled work, startup) it uses the instance's global language. Logs always use the global language.
- **Stored keys.** Tool descriptions, schema descriptions and module-level tables hold catalog keys; `Tool.spec()`, `localize()` and `TranslatedDict` translate them when read. Text with params that must stay lazy is `Text("key", name=value)`.
- **Prompts.** Model-facing instructions live in `prompts/zh.py` and `en.py` and are read with `prompt_text("NAME", name=value)`. Templates use `{name}` and `{{ }}` for literal braces.
- **Markers in messages** (`[image]`, `[QQ image ref …]`) follow the bot language; parsers accept every language, because stored history keeps older markers.
- **Word lists** (control words, emotion phrases, stopwords) list every language. English phrases match whole words. Control words accept both languages (`stop` / 停, `approve` / 同意).
- **English search.** Memory and the knowledge base index English words with a light stem as well ("meetings" → "meet").
- **Lines that must stay Chinese** (word lists, bilingual control words, internal IDs) carry `# i18n: ok`; a file made of language data carries `i18n-check: language-data`.

## Plugins and Skills

- A plugin ships `locales/<locale>.json` next to `main.py` and calls `self.t("key", name=value)`. Text in `metadata.yaml` and `_conf_schema.json` may be a map: `{"zh-CN": "默认城市", "en": "Default city"}`. The stored default stays plain text; the API shows the viewer's language. See `skill/builtin/shiritai-plugin-dev/assets/hello_world/`.
- A Skill may ship `SKILL.en.md` (and `references/x.en.md`) next to the original; it's read instead when the conversation is in English.

## Checks

```bash
python3 scripts/check_i18n.py
```

The script fails when:

- a file gains hardcoded Chinese text compared with `scripts/i18n-baseline.json` (comments and docstrings don't count), or
- the catalogs differ between locales.

After migrating a file, run `python3 scripts/check_i18n.py --update` to lower the baseline. Don't raise it to make a check pass; move the text into a catalog instead.

## Adding a language

1. Add the code to `Locale` in `src/shiritaibot/i18n/__init__.py` and to `LOCALES` in `web/src/i18n/index.ts`, with its name written in that language.
2. Copy `src/shiritaibot/locales/zh-CN/` and `web/src/locales/zh-CN/` to the new code and translate them.
3. Add `src/shiritaibot/prompts/<code>.py`, register it in `prompts/__init__.py`, and translate the constants. Anything missing falls back to Chinese.
4. Run the tests and `scripts/check_i18n.py`.

## Compatibility

New config fields such as `locale` are forward-only. Configs reject unknown fields, so once a newer version has saved `config.toml`, an older version will refuse to load it.
