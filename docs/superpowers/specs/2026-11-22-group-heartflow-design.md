# 群聊主动回复模式与心流状态机

日期：2026-11-22　状态：已接入 OneBot 11 与 WebUI

## 群聊主动回复设置

在 WebUI 的「设置 → 通用设定 → 群聊上下文感知」中，用「群聊主动回复」选择下列三种模式。设置作用于已启用群聊上下文的群，发言额度和心流状态按群会话独立计算。

| 模式 | 遇到没有 @ 机器人、也没有命中唤醒词的普通群消息时 |
| --- | --- |
| **关闭主动回复**（默认） | 按现有设置记录群上下文。主动回复不启动任务，也不调用模型。 |
| **简单主动回复** | 沿用现有 OneBot 群聊插话逻辑。每条符合条件的消息按配置概率抽取，命中后让主模型决定接一句还是输出 `<pass>`。 |
| **心流主动回复** | 将短时间内的群消息合并观察。轻量模型判断是否适合接话，主模型负责措辞。刚和群友说过话时，机器人会留意没有再次 @ 它的追问。 |

三种模式都沿用现有的 @、关键词唤醒、命令及插件处理顺序。群上下文总开关 `group_context.enabled` 关闭时，暂停两种主动回复策略，保留用户选择的模式。首版接入现有 OneBot 11 群消息入口，协调器使用现有群会话 ID，供其他适配器后续接入。定时主动任务继续由 `ProactiveEngine` 负责。

## 简单主动回复的兼容约定

现有 [OneBot 群消息处理](../../../src/shiritaibot/adapters/onebot11.py) 会先处理命令与插件已经消费的消息。对进入 `maybe_interject` 的普通群消息，检查群上下文开关、消息内容、运行时忙碌状态和免打扰时段，再检查本群冷却、滚动一小时额度，最后按概率抽取。

沿用原配置和默认值：`interject_probability = 0.02`、`interject_cooldown = 900` 秒、`interject_max_per_hour = 4`。**抽中即计一次**，随后提交无工具的群聊 `chat` 回合。主模型输出 `<pass>` 时群里看不到消息，已经开始的冷却与已用额度照常保留。简单模式无需配置 `light` 模型。

## 心流如何接话和退场

例如，群友 @ 机器人问「怎么去场馆」，机器人答完后，群友又发「那末班车呢」。此时仍在同一段对话里，裁判可以把这条短消息与机器人刚才的答复一起判断。如果群友已经转去聊晚饭，机器人就退出跟聊。整个过程由群消息、防抖定时器以及发言结果驱动，无需后台轮询。

| 状态 | 何时观察 | 转移规则 |
| --- | --- | --- |
| `LURK` 潜水 | 初始状态。普通消息聚合后以较高门槛观察。 | 主动发言成功后进入专注。连续三次低分或 `<pass>` 后短休一个潜水观察间隔，再回到潜水。 |
| `FOCUS` 专注 | 结合机器人刚说的话，优先判断群友是否在接它的话。缩短防抖和观察间隔。 | 主动发言成功后刷新窗口。焦点超时、明确转题或连续两次观察未发言时回到潜水。 |
| `REST` 休整 | 暂停主动观察。 | 连续发言达上限或精力不足时进入常规休整。休整期满且精力足够发下一句时回到潜水。 |
| `QUIET` 免打扰 | 复用 `proactive.quiet_start`、`quiet_end` 和 `timezone`。 | 进入时作废待观察批次与待发插话。时段结束后，下条消息从潜水开始处理。 |

免打扰优先。显式唤醒随时走原有被动回复路径；在免打扰以外，被动答复成功发出后进入或刷新专注，连续主动发言数归零，精力原值保留。被动答复本身不占主动额度。任何一次主动发言成功后，都先检查连续上限与剩余精力，再决定是否进入或刷新专注。焦点窗口设为零时跳过专注，精力与小时额度仍然生效。

### 从一批消息到一次发言

1. **等群友说完。** 每群保留一个有界缓冲区。潜水时默认等最后一条消息后 4 秒，专注时等 2 秒。持续刷屏时，从首条起满 12 秒或已收 8 条就结算这一批。正在观察时到达的消息进入下一批，同一群最多有一次主动观察或发言在途。
2. **先做本地检查。** 检查当前模式、免打扰、休整、会话忙碌、小时额度、精力和观察间隔。忽略纯命令、无有效内容及纯复读。潜水时两次裁判调用默认至少间隔 20 秒，专注时为 6 秒。观察间隔从裁判调用开始计算，失败也受节流。
3. **让轻量模型判断是否接话。** 输入限于本群允许使用的上下文、本批新消息和当前状态。专注时附上机器人最近一次已发出的相关答复。裁判评估内容价值、社交合适度、时机和连贯性，并判断是否已转题。优先复用 `ProviderManager.decide("light", …)`，没有可用决策结果时可在同一超时预算内走 `light` 文本模型，校验结构化评分。裁判不可用、超时或结果无效时，本批静默结束。
4. **生成候选回复。** 综合分达标后，使用现有群聊 `chat` 插话提示和记忆权限，禁用工具。主模型可以输出 `<pass>`。有效低分与 `<pass>` 才累计连续未发言次数；超时、取消和过期属于执行结果，不据此判断群友冷落了机器人。
5. **发送前再看一次群里发生了什么。** 每次观察保存消息序号和唤醒序号。生成期间若收到新的显式唤醒、普通消息增量超过 5 条、模式切换或已进入免打扰，作废候选回复。被动唤醒到达时先使旧候选失效，无需等裁判或主模型释放锁。检查在写入可见回复和进入出站队列之前完成。
6. **按发送结果记账。** 心流按协议端确认成功的一次主动发言扣精力、占小时额度并更新焦点。同一回合即使拆成多段也只计一次，首段成功即算发言。发送在途时预留一次额度，余下分段或重试按同一回合去重。整轮被插件拦截或投递终止且没有成功分段时释放预留。低分、`<pass>` 与过期候选均不扣发言额度。

### 精力和发言门槛

精力按群从 1 开始，随经过时间线性恢复，默认 45 分钟从 0 恢复到 1。设连续主动发言上限为 $N$，第 $k$ 次主动发言的消耗为 $0.90\,w_k / \sum_{i=1}^N w_i$。首次从潜水插话也算第 1 次。默认 $N=3$ 时：

| 精力曲线 | 权重 | 连续三次发言各自消耗（约值） |
| --- | --- | --- |
| `flat` | $1$ | 0.30、0.30、0.30 |
| `linear` | $1 + 0.5(k-1)$ | 0.20、0.30、0.40 |
| `exponential`（默认） | $1.8^{k-1}$ | 0.15、0.27、0.48 |

积极度越高，裁判放行所需的基础分越低。进入专注可降低门槛，连续发言和精力下降会把门槛抬高。若已启用群作用域情绪，可用作小幅修正，读取失败时修正量为零。小时额度、连续上限与免打扰始终优先于评分。

## 配置与升级

[群上下文配置](../../../src/shiritaibot/config/__init__.py) 的 `group_context.interject_mode` 取值为 `off`、`simple` 或 `heartflow`。心流专用参数在 `group_context.heartflow` 子表中保存。

| WebUI 显示条件 | 设置 | 默认值 |
| --- | --- | --- |
| 始终显示 | 群聊主动回复模式 | 关闭主动回复 |
| 简单 | 插话概率、冷却秒数 | 0.02、900 |
| 简单或心流 | 每群每小时上限（沿用 `interject_max_per_hour`） | 4；简单按抽中次数，心流按成功发言次数 |
| 心流 | `activity` 积极度、`focus_seconds` 专注秒数、`max_streak` 连续上限 | 0.5（范围 0–1）、150、3 |
| 心流高级设置 | `rest_seconds` 常规休整秒数、`energy_curve`、`energy_recovery_minutes` | 600、`exponential`、45 |
| 心流高级设置 | `debounce_seconds` 潜水防抖、`min_judge_interval` 潜水观察间隔、`developer` 调试日志 | 4 秒、20 秒、关闭 |

加载旧配置时，仅当新字段缺失才读取旧布尔值 `group_context.interject`：`true` 映射到简单，`false` 或缺失映射到关闭。显式新模式优先，未知值按配置错误提示。保存设置时写入新模式，保留已有概率、冷却、额度及未选模式的参数。升级不会自动启用心流。

## 实现与验收

- **接入点。** 在 OneBot 当前处理普通群消息的位置按模式分派，仅心流实例接收普通消息、被动唤醒到达和实际回复结果。心流沿用现有群会话 ID，状态、定时器和缓冲区按群隔离。切出心流、关闭群上下文或停用适配器时取消待处理工作，使旧回调失效。心流的瞬时状态不落盘。
- **生成与出站。** 心流复用群聊插话回合生成候选，在 OneBot 确认后写入助手历史。每个出站分段关联同一观察 ID。候选从观察开始最多保留 60 秒，出站和重试前都复核有效性。每群在事件循环中同步更新状态，等待模型和网络回执期间可以继续收消息。
- **调试。** 通过日志记录群会话、状态转移原因、分数、门槛与作废原因。无需新增状态监控页面。
- **验收三种模式。** 以新装、旧开关开/关、旧配置含自定义参数、新旧字段同时存在为样例，核对加载、WebUI 展示和保存后重载。关闭模式在普通群消息下零主动模型调用；简单模式用确定的抽样结果验证冷却、额度与 `<pass>`；只有心流模式调用裁判。
- **验收跟聊与退场。** 覆盖拆句和持续刷屏、被动答复后未 @ 的追问、转题、连续发言达上限、焦点过期和免打扰期间的被动唤醒。用两个群交错发消息，验证只有发生互动的群进入专注。
- **验收竞态与失败。** 在裁判和生成期间分别插入显式唤醒、切换模式；模拟低分、`<pass>`、超时、发送失败和重复回执。检查群内实际发言、助手历史与计数，确认过期内容不会在群里出现，重试成功的同一回合只记一次。
